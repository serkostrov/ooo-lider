В Приложении № 2 зафиксированы два оплачиваемых этапа. Отдельного «Этапа 3» в договоре нет.

2. Цель Этапа 2

Закрыть блоки контроля, мобильной работы, экрана руководителя и выгрузок; развернуть систему на сервере заказчика; провести приёмочное тестирование и обучение.

3. Что входит в Этап 2

Блок 7. Проверка и приёмка

  • Исполнитель не закрывает этап сам — направляет на проверку.
  • Закрытие уполномоченным; на проверку только при отмеченных условиях.
  • Возврат с причиной в карточке и истории.

Работы: прогон и доводка сценария; проверка блокировок; согласование роли «уполномоченного». Базовая логика в системе уже есть.

Блок 8. Папка исполнительной документации

  • Автонакопление документов с признаком «в папку ИД».
  • Перечень недостающих (этап, исполнитель, дата отправки, срок ожидания).
  • Контроль комплектности перед герметичностью / опрессовкой.
  • Предупреждение (или блокировка) при закрытии с неполной папкой.

Работы: экран «Папка ИД» на объекте; список собранного / недостающего; правила критических этапов; валидация при приёмке. Флаг в справочнике уже есть — сводного экрана нет.

Блок 9. Уведомления

  • Напоминание по сроку, просрочка, нет ответа по документу, этап на проверке, нет исполнителя.
  • Переход в карточку этапа.
  • Дублирование в Telegram и email.

Работы: матрица событий; лента уведомлений; Telegram-бот и привязка пользователей; email (SMTP); настройки каналов.

Блок 10. Мобильные рабочие места

Роли и доступы — уже Этап 1. В Этап 2 входит мобильная работа.

  • Упрощённый UI с телефона: текущий этап, крупные кнопки.
  • Отметка условий закрытия.
  • Нештатная ситуация — выделение объекта для всех.
  • Добавление работы вне регламента.

Блок 11. Экран руководителя

  • Метрики по объекту (закрытые, просроченные, без ответа, на приёмке, без исполнителя).
  • Линейная схема этапов с переходом в карточку.
  • Списки просроченных / приближающихся: смена срока, запрос статуса.
  • Массовый сдвиг сроков, заполнение пустых сроков.
  • Готовность по видам работ, нагрузка по сотрудникам.

Блок 12. История и выгрузки

  • Журнал действий по объекту.
  • Выгрузка этапов (условия, сроки, статусы, исполнители) в Excel.
  • Печать перечня этапов.

Оргчасть (обязательна)

  • Развёртывание на сервере заказчика.
  • Приёмочное тестирование.
  • Обучение пользователей.
  • Акт сдачи Этапа 2.

5. Что остаётся «на третий этап»

В договоре третьего этапа нет. Ниже — постдоговорной контур.

5.1. Вне договора (только доп. соглашение)

  • Учёт материалов и инструмента
  • Детализация по бригадам
  • Табель рабочего времени
  • Интеграции с внешними системами
  • Автоподача заявок и обмен с контрагентами

5.2. Из ТЗ — «после показа» / следующий шаг

  • Отдельные кабинеты ролей (планшет/телефон прораба, столы ПТО и офиса)
  • Отправка заявки на почту из системы (Timeweb и т.п.)
  • PDF заявки по фирменному бланку
  • Автоподтверждение получения заявки адресатом

6. Зависимости от заказчика

  • Сервер / домен для финального деплоя
  • Решение по Telegram-боту и email (SMTP)
  • Список пользователей для обучения
  • Подтверждение этапов с жёстким контролем папки ИД (герметичность / опрессовка)
